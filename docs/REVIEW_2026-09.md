## 一、设计不合理之处 · 需完善功能 · 建议删减内容

### 1.1 最高优先级：文档-代码-测试三方失协（BentoGrid 断链）

- `PROJECT.md` (F8~F10, M3) 与 `TEST_READY.md` (F8 契约) 均声称：`BentoGrid` 挂载于首页 7 列主看板，承载 `TechMatrixCard` 等卡片；
- e2e 契约硬性依赖：`e2e/utils/client.mjs:253` 直接检查 `frontend/components/bento/BentoGrid.tsx` 存在性；`e2e/test_tech_matrix_challenger.mjs` 断言 BentoGrid 挂载 `<TechMatrixCard` 且 TECH_MATRIX_ITEMS 导出存在；Tier1~4 共 15+ 用例调用 `inspectBentoGrid()`；
- **但 `app/page.tsx` 从未 import BentoGrid**——代码漂移导致 `components/bento/` 9 个组件全部沦为死代码（约 115KB），其中 `TechOrbitRadar`、`CosmosGraph` 还各自打包 three.js（约 600KB+ 冗余风险）。

**处置决策（复活而非全删）**：直接删除全部 9 个组件将迫使 e2e F8 契约、`test_tech_matrix_challenger`、`test_3d_adversarial`、`test_m1_container_overflow` 等多个套件连锁改写，风险远大于收益。因此：

| 组件 | 处置 | 理由 |
|---|---|---|
| `BentoGrid` / `SpotlightCard` / `TechMatrixCard` / `GardenMindFlowCard` | **复活**：挂载回首页 | 满足 e2e F8 契约 + PROJECT.md 规格 + 首页美化目标三合一 |
| `TechOrbitRadar` | **删除** | 零引用；测试仅断言其"不在 BentoGrid 中" |
| `TechRadarCard` | **删除** | 零引用；e2e 对应标志为硬编码 true，无文件依赖 |
| `CosmosGraph` | **删除** | 零引用；需同步移除 `test_3d_adversarial.mjs` Test 1.1 模块 |
| `LifePulseCard` / `TiltCard` | **删除** | 零引用（projects 页 Tilt 为自实现局部函数） |
| `now/components/NomadHudPulse.tsx`、`VinylRecordPlayer.tsx` | **删除** | 零引用死代码（Tier 套件仅断言 `rotatingVinylRemoved: true`，即"已移除"为正确状态） |

### 1.3 需完善的功能

1. **缺全局 404 页面**：`app/` 下无 `not-found.tsx`，错误路径裸奔默认页；
2. **缺加载骨架**：无 `loading.tsx`，首页/列表页数据慢时白屏；
3. **ReadingProgress 仅博文详情页挂载**，journey/about 长页未覆盖；
4. **搜索页体验单薄**：300ms 防抖可用，但无空态插画、无结果高亮、无动效；
5. **技术栈 CMS 缺失**：后端 18 个实体中无 TechStack 实体，技术矩阵无法后台管理（本次以静态数据+配置兜底过渡，列为后续债务）；
6. **e2e 与实现同步**：`test_m2_layout_spacing_adversarial.mjs` 以 `latest_thoughts` 作为罗盘下游锚点，首页引入 Bento 后需同步锚点为 Bento 挂载点。

### 1.4 建议删减内容汇总

- 死代码 7 文件（见 1.1 表）；
- 首页「随记速览」区块：与 Bento 拍立得卡功能重复，且 memos 有独立页面，删除以减少同质化区块（e2e 无此区块断言，安全）；

## 三、首页专项诊断与整体美化方案

### 3.1 现状问题诊断

**视觉层面**
1. 中段 6 个区块（博文/项目/随记/旅程/Now/About）视觉完全同质：均为「小标签 + 大标题 + View all 链接 + 网格卡片」，色彩上仅靠标签色相区分，无大小、密度、材质的节奏对比；
2. Now 区块 `bg-secondary/50` 灰底平铺，与铁律 3 的「磨砂白瓷/曜石黑 + 极光 HUD」质感脱节；
3. About 区块默认头像硬编码 Unsplash 人像（违反铁律 2），且是全页最平淡的收尾。

**布局层面**
4. 罗盘解构 100% 退场后，迎面而来的是又一张普通三卡网格，"电影级开场 → 平铺直叙"落差极大，叙事断裂；
5. `space-y-16 md:space-y-24` 均匀间距让 6 个区块无主次之分，页面越长越疲劳。

**交互层面**
6. 中段所有卡片仅有 `hover:border-*/hover:scale-105`，与 Hero 区的 Spotlight 光斑 + 3D Tilt + 流光边框相比判若两站；死代码 `SpotlightCard` 恰好就是为此而生却未挂载；
7. 无任何入场动效（首屏以下内容瞬间平铺出现），浪费滚动叙事空间。

### 3.2 整体美化方案

**目标结构（保持 max-w-6xl 受控栅格与 e2e m2 断言的容器规范）：**

```
AnnouncementBanner
└─ HeroCinematicStage        电影级全息 HUD（保留，微调）
└─ HeroPinnedScrollytelling  3D 罗盘滚动解构（保留）
└─ max-w-6xl 容器（space-y-16 md:space-y-24 pt-8 sm:pt-12 pb-16 保持）
   ├─ BentoGrid 全息看板     [复活挂载] 12 列非对称：
   │   ├─ TechMatrixCard      col-span-7  全栈技术矩阵（Spotlight 壳）
   │   ├─ GardenMindFlowCard  col-span-5  心智流 HUD（Spotlight 壳）
   │   ├─ 精选博文洞察卡       col-span-4  真实 featuredPost
   │   ├─ 拍立得窥镜卡         col-span-4  真实 latestMemo
   │   ├─ 足迹航海入口卡       col-span-4  真实 latestJourney（无旅程时优雅空态，不展示虚构城市）
   │   └─ [新增] Now 心跳 HUD 卡 col-span-12/嵌入  心跳呼吸灯 + 四维状态速览
   ├─ Latest Thoughts         3 篇博文（补 whileInView stagger + Ken Burns）
   ├─ Featured Projects       精选项目（补入场动效）
   ├─ Journey Preview         3 段旅程（补入场动效）
   ├─ Now 四格                升级极光引言边线 HUD 质感
   └─ About 收尾卡            头像走 settings + Spotlight 交互
   （随记速览区块删除——Bento 拍立得卡已覆盖）
```

**关键改造点：**
1. **Bento 复活**：`app/page.tsx` 传入真实 `featuredPost / latestMemo / latestJourney / now` 数据；`GardenMindFlowCard` 的虚构坐标/92% 假进度改为 now 记录驱动 + 中性文案兜底；无旅程数据时足迹卡展示「等待第一段旅程发布」空态而非 Tokyo 假数据；
2. **动效原语**：新建 `components/ui/motion-primitives.tsx`（`RevealStagger` / `RevealItem` / `KenBurnsImage`），全站复用，`viewport={{ once: true }}` + `motion-reduce` 兜底；
3. **Hero 全屏化**：`min-h-[500~620px]` → `min-h-[calc(100svh-4rem)]`（保留底部羽化与滚动引导），与 sticky 罗盘形成两屏完整叙事；
4. **Now HUD 化**：极光渐变引言边线 + 双层呼吸探活灯（复用 Hero 徽章语言），四格改为玻璃拟态卡；
5. **About 收尾**：`settings.avatar` 兜底本地 SVG 占位（去 Unsplash），加 Spotlight 光斑与呼吸边框；
6. **e2e 同步**：`test_m2_layout_spacing_adversarial.mjs` MODULE 3 下游锚点从 `latest_thoughts` 扩展为 Bento 挂载点。

**验收标准**：`pnpm build` 0 错误、`mvn test` 106 绿灯、`node e2e/run-all.mjs --mock-oracle` 全量通过、双主题截图核查三层级景深。
